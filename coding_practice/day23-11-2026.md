1. What is CI/CD?
CI/CD stands for:
- CI = Continuous Integration
- CD = Continuous Delivery / Continuous Deployment
In simple language, CI/CD automates the process of building, testing and deploying application code.

What is CI (Continuous Integration)?
CI means automatically integrating and testing developers' code whenever they push changes to a shared repository.

Real company CI/CD workflow
1. Developer writes code
   
   Develops a Java banking application.
2. Git / GitHub
   
   Developer pushes code to a GitHub repository.
3. CI pipeline
   
   Jenkins or GitHub Actions starts the pipeline.
4. Build and Test
   
   Maven compiles the Java code and executes tests.
5. Docker
   
   Creates a Docker image of the application.
6. AWS ECR
   
   Stores the Docker image in the container registry.
7. CD / Deployment
   
   Updates Kubernetes deployment configuration.
8. AWS EKS
   
   Kubernetes deploys the updated application.
9. Monitoring
   
   Prometheus, Grafana or New Relic monitors the application.

====================
GitLab CI/CD is a feature of GitLab that automates building, testing and deploying applications.

Without CI/CD:

A developer writes code → manually builds it → tests it → creates a Docker image → deploys it.

With CI/CD:

A developer pushes code to GitHub → pipeline automatically builds, tests and deploys the application.


Core components of GitLab CI/CD

1. .gitlab-ci.yml
This is the most important file in GitLab CI/CD.

2.Pipeline
A pipeline is the complete automation process.

3. Stages
Stages represent the different phases of your pipeline

4.Jobs
A job is an individual task inside a stage.

5. Executor: An executor defines the environment in which a GitLab Runner executes a job.
6. VariablesL:Variables store values
7. Cache
Cache saves reusable files between pipeline jobs or runs to reduce repeated work.

Example: Cache Maven dependencies so that Maven does not need to download the same dependencies repeatedly.
