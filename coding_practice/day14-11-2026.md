# **1. Linux – Theory and Concepts**

Linux is an operating system used to manage servers and run applications.

| Concept         | Simple explanation                                |
| --------------- | ------------------------------------------------- |
| File System     | Organizes files and directories in Linux.         |
| Permissions     | Controls who can read, write, or execute files.   |
| Users & Groups  | Manages access for different users.               |
| Processes       | Programs currently running on a server.           |
| Services        | Background applications, like Nginx or Docker.    |
| Networking      | Helps servers communicate with each other.        |
| SSH             | Allows us to connect to a remote server securely. |
| Cron Jobs       | Runs tasks automatically at scheduled times.      |
| Disk Management | Checks disk space and storage usage.              |
| Logs            | Records system and application activities.        |

**Example:** In a production environment, engineers use Linux commands to check server health, disk space, application processes, and logs.

# **2. Docker – Theory and Concepts**

Docker is a containerization platform that packages an application with its dependencies so it can run consistently in different environments.

| Concept         | Simple explanation                                       |
| --------------- | -------------------------------------------------------- |
| Image           | A blueprint used to create containers.                   |
| Container       | A running instance of an image.                          |
| Dockerfile      | Instructions to build a Docker image.                    |
| Docker Engine   | Runs and manages containers.                             |
| Docker Volume   | Stores data permanently, even if a container is deleted. |
| Docker Network  | Allows containers to communicate.                        |
| Docker Compose  | Runs multiple containers together.                       |
| Docker Registry | Stores and distributes Docker images.                    |
| Port Mapping    | Connects a container port to a host port.                |
| Docker Layers   | Different steps that make up a Docker image.             |

**Example:** You have a Java application. You create a Docker image and run it inside a container so it works consistently on different servers.

# **3. AWS – Theory and Concepts**

AWS is a cloud platform that provides services like servers, storage, networking, and databases over the internet.

| Concept / Service | Simple explanation                                    |
| ----------------- | ----------------------------------------------------- |
| EC2               | Virtual server in AWS.                                |
| VPC               | Your private network in AWS.                          |
| Subnet            | A smaller network inside a VPC.                       |
| IAM               | Manages users, roles, and permissions.                |
| S3                | Stores files and objects.                             |
| EBS               | Block storage for EC2 instances.                      |
| RDS               | Managed relational database.                          |
| Load Balancer     | Distributes incoming traffic across servers.          |
| Auto Scaling      | Automatically increases or decreases server capacity. |
| Route 53          | AWS DNS service.                                      |
| CloudWatch        | Monitors AWS resources and applications.              |
| CloudTrail        | Records AWS account activities and API calls.         |
| EKS               | Managed Kubernetes service in AWS.                    |
| Lambda            | Runs code without managing servers.                   |
| Security Groups   | Controls inbound and outbound traffic for resources.  |

**Example:** In a banking application, EC2 runs the application, RDS stores customer data, S3 stores documents, and Load Balancer distributes traffic.

# **4. Kubernetes – Theory and Concepts**

Kubernetes is a container orchestration platform. It manages containers, scaling, networking, and application availability.

| Concept      | Simple explanation                                          |
| ------------ | ----------------------------------------------------------- |
| Cluster      | A complete Kubernetes environment.                          |
| Node         | A machine that runs applications.                           |
| Pod          | The smallest deployable unit in Kubernetes.                 |
| Deployment   | Manages and maintains application pods.                     |
| ReplicaSet   | Maintains the required number of pods.                      |
| Service      | Provides stable network access to pods.                     |
| ClusterIP    | Allows internal cluster communication.                      |
| NodePort     | Exposes an application through a node port.                 |
| LoadBalancer | Exposes an application using an external load balancer.     |
| Namespace    | Divides a cluster into separate logical environments.       |
| ConfigMap    | Stores non-sensitive configuration.                         |
| Secret       | Stores sensitive configuration data.                        |
| Ingress      | Manages HTTP/HTTPS access to services.                      |
| DaemonSet    | Runs a pod on each selected node.                           |
| StatefulSet  | Manages applications that need stable identity and storage. |
| HPA          | Automatically scales pods based on metrics.                 |
| PV           | Represents persistent storage.                              |
| PVC          | Requests storage for an application.                        |
| kubelet      | Ensures containers run inside a node as instructed.         |
| kube-proxy   | Helps manage Service networking.                            |

**Example:** In a banking application, Kubernetes runs multiple Java application pods. If one pod crashes, Kubernetes can create another pod to maintain the required number of replicas.
