Monitoring
Checks whether a system is working properly
Focuses on predefined metrics and alerts.
Tells you something is wrong.
Example: CPU usage reaches 90%, so an alert is triggered.

Observability
Helps understand why a system is having problems.
Focuses on investigating unknown issues.
Helps you find why it is wrong.
Example: You investigate logs, metrics, and traces to find why CPU usage reached 90%.

What is New Relic?
A monitoring and observability tool used to monitor applications, servers, containers and Kubernetes clusters.


New Relic integration with AWS EKS – Steps
1. Create New Relic Account – Sign up and get your License Key.
2. Connect to EKS – Connect your AWS EKS cluster.
3. Add Helm Repository – Configure the New Relic Helm chart repository.
4. Install New Relic Agent – Deploy New Relic monitoring agents inside EKS.
5. Collect Metrics – Agents collect CPU, memory, pod, node and cluster metrics.
6. Send Data – New Relic agents send monitoring data to New Relic Cloud.
7. Configure Dashboard – View EKS cluster health and application performance.
8. Configure Alerts – Receive notifications for high CPU, memory usage and pod failures.

Popular tools:
- Monitoring: Prometheus, Nagios, Zabbix.
- Observability: Grafana, Jaeger, OpenTelemetry.

Troubleshooting: 

Troubleshooting Cluster Autoscaler – this is the issues today I face CrashLoopBackOff
Meaning: Cluster Autoscaler pod repeatedly crashes because of configuration errors, IAM permission issues, or incorrect cluster settings.

Solution – Step by Step

1. Check pod status
kubectl get pods 


2. Check error logs
kubectl logs 


3. Describe the pod
kubectl describe pod

4. Check IAM permissions

Ensure the Cluster Autoscaler IAM role has the required permissions to manage EC2 Auto Scaling Groups.

5. Check configuration

Verify:
- Correct cluster name.
- Correct AWS region.
- Correct Auto Scaling Group tags.
- Correct IAM role (IRSA).

6. Restart the deployment after fixing the issue
kubectl rollout restart deployment cluster-autoscaler -n kube-system


7. Verify
kubectl get pods -n kube-system
