ELK Stack: A log management and analytics stack used to collect, process, store, search, and visualize logs in real time.
- E – Elasticsearch
- L – Logstash
- K – Kibana

2. Log Parsing
Log Parsing: Extracting meaningful fields like timestamp, log level, IP address, and error message from raw logs to make them searchable and understandable.

Example: Raw log → Structured JSON log.

3. Core Components
Elasticsearch
A distributed search and analytics engine that stores, indexes, and searches log data using JSON documents.
- Index: Logical collection of documents.
- Document: Individual JSON record.
- Shard: A partition of an index used for scalability.
- Replica: Copy of a shard used for high availability.
Logstash
A data processing pipeline that collects, parses, transforms, and forwards logs to Elasticsearch.
- Input: Collects logs from sources.
- Filter: Parses and transforms logs.
- Output: Sends processed logs to Elasticsearch.
Kibana
A web-based visualization tool used to search, analyze, and create dashboards from Elasticsearch data.
- Dashboard: Visual representation of log data.
- Discover: Search and explore logs.
- Visualization: Charts, graphs, and tables.

4. Logstash Filters
- Grok: Parses unstructured logs into structured fields.
- Date: Converts timestamps into standard date format.
- GeoIP: Adds geographical information using IP addresses.
- Mutate: Renames, removes, or modifies fields.

Shards
- Primary Shard: Original data partition.
- Replica Shard: Copy for HA and read performance.
- Node: Elasticsearch server.
- Cluster: Group of nodes.

Formulas
- Total Shards = P × (R + 1)
- Minimum Nodes = R + 1
- Failure Tolerance = R
- Primary Shards = Data Size ÷ Shard Size

Shard Planning
- Recommended shard size: 10–50 GB
- Too many shards → Memory overhead
- Replicas → HA + Read performance
- Replicas do not improve write throughput.
====================
ILM

ILM: Automates index lifecycle management to reduce cost and manual effort.
- Hot: Active writes
- Warm: Less frequently accessed
- Cold: Rarely accessed
- Frozen: Very rarely accessed
- Delete: Removes old indices
ILM Operations
- Rollover: Creates new index based on size/age.
- Shrink: Reduces shard count.
- Move: Transfers data to cheaper storage.
- Delete: Removes expired data.

50GB OR 7 days → whichever occurs first.
