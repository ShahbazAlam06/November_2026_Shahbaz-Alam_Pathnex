## **1. What is SSL/TLS?**

**SSL (Secure Sockets Layer) and TLS (Transport Layer Security)** are security protocols that encrypt communication between a client (browser) and a server.

TLS is the modern and secure replacement for SSL.

## **2. Why do we use TLS?**

1. **Encryption:** Protects data from hackers.
2. **Authentication:** Verifies that we are communicating with the correct server.
3. **Data Integrity:** Ensures data is not modified during transmission.

**Real-time example:** When you log in to a banking application, TLS protects your username, password and banking information.

## **3. TLS flow (short)**

**1. Client Hello**

Browser requests a secure connection and sends supported TLS versions and cipher suites.

**2. Server Hello**

Server selects TLS settings and sends its digital certificate.

**3. Certificate Verification**

Browser verifies the certificate, domain name and certificate chain.

**4. Key Exchange**

Client and server establish shared session keys.

**5. Secure Communication**

Both sides exchange encrypted data using session keys.

HTTPS connection established

## **4. TLS certificate process step by step (production)**

Suppose your company has a domain: `banking.example.com`.

STEP-BY-STEP WORKFLOW

**Step 1: Generate a private key**

```
openssl genrsa -out server.key 2048
```

- Creates a private key.
- Keep it secret. Never share it.

**Step 2: Generate CSR**

```
openssl req -new -key server.key -out server.csr
```

- CSR = Certificate Signing Request.
- Contains your public key and domain information.

**Step 3: Submit CSR to CA**

Submit the CSR to a Certificate Authority (CA), such as DigiCert.

**Step 4: Domain validation**

CA verifies that you own or control the domain.

**Step 5: Receive certificates**

CA provides:

- `server.crt` – server certificate.
- Intermediate certificate(s) – certificate chain.

**Step 6: Configure the server**

Configure Nginx, Apache, or your load balancer with:

- Certificate file (`server.crt`)
- Private key (`server.key`)
- Intermediate certificate chain

**Step 7: Restart or reload the service**

For Nginx:

```
sudo nginx -t
sudo systemctl reload nginx
```

**Step 8: Verify TLS**

```
openssl s_client -connect banking.example.com:443 -servername banking.example.com
```

This helps verify the TLS connection and certificate chain.

## **5. Important terms to remember**

| Term        | Meaning                                |
| ----------- | -------------------------------------- |
| Private Key | Secret key kept on the server          |
| Public Key  | Public key included in the certificate |
| CSR         | Request sent to CA for a certificate   |
| CA          | Organization that issues certificates  |
| Certificate | Proves server identity                 |
| HTTPS       | HTTP communication secured using TLS   |
| SSL         | Old, deprecated security protocol      |
| TLS         | Modern security protocol               |

Production tip

- Never expose your private key.
- Always use TLS 1.2 or TLS 1.3.
- Monitor certificate expiry.
- Renew certificates before expiration.
- Automate renewal using tools like Certbot where supported.

**Best tip to remember:** CSR → CA Validation → Certificate → Server Configuration → TLS Verification.
